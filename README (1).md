# Inventory — учет оборудования со сканером штрихкодов

Лёгкая консольная система инвентаризации на чистом Python. Отвечает на три вопроса: **что это за устройство, где оно стоит сейчас и по какому адресу его искать**. Без серверов, без зависимостей, без установки: один файл и одна база SQLite.

## Зачем это нужно

Когда техники больше нескольких единиц, начинается хаос: ноутбук «где-то в 305-м», принтер переехал, а в таблице он числится на старом месте. Inventory решает это так:

- каждая единица получает уникальный код (штрихкод или инвентарный номер);
- у каждого помещения есть название и адрес;
- любое перемещение фиксируется в истории;
- раз в какое-то время проводится инвентаризация, и расхождения видны сразу.

## Возможности

| Функция | Что делает |
|---|---|
| Места и адреса | Кабинеты, шкафы, склады и их физический адрес (город, здание, этаж, кабинет) |
| Учет техники | Код, название, категория, серийный номер, заметка, текущее место |
| Работа со сканером | Сканируете код, и сразу видите карточку: что это и где стоит |
| Перемещение | Выбираете место назначения и сканируете всё, что перенесли |
| Инвентаризация | Сканируете всё в помещении, получаете отчет: найдено, не найдено, чужое, неизвестное |
| История | Полная цепочка перемещений каждого устройства с датами |
| Поиск | По коду, названию, серийному номеру или категории |
| Экспорт | CSV для Excel (кодировка UTF-8 с BOM, разделитель `;`, кириллица читается корректно) |

## Как это работает

### Сканер как клавиатура

Штрихкод-сканер не требует драйверов и SDK. Он работает в режиме USB HID: «печатает» считанный код и нажимает Enter. Поэтому программа читает его обычным `input()`, и один и тот же интерфейс подходит и для сканера, и для ручного ввода. Если штрихкода нет, код можно набрать руками.

### Модель данных

База SQLite состоит из трех таблиц:

```
locations ──┐
  id, name, address
            │ 1
            │
            ▼ N
equipment ──────────────┐
  id, code (UNIQUE),    │ 1
  name, category,       │
  serial, note,         ▼ N
  location_id,       movements
  last_check           equipment_id, from_loc, to_loc, moved_at
```

- `equipment.code` уникален: одно устройство, один код.
- `equipment.location_id` хранит *текущее* место, а `movements` ведет журнал всех перемещений.
- Все связи заданы внешними ключами, поэтому историю и адреса можно сопоставлять без дублирования данных.

### Инвентаризация

Алгоритм сверки простой и надежный. Для выбранного места программа берет из базы ожидаемый набор кодов, затем вы сканируете то, что реально стоит на месте. После этого сравниваются два множества:

- **найдено**: код есть и в базе, и в скане. Для него обновляется дата последней проверки;
- **не найдено**: числится здесь, но не отсканирован (возможна пропажа или перемещение без учета);
- **чужое**: отсканирован, но в базе числится в другом месте. Его можно сразу перенести одним подтверждением, и перемещение попадет в историю;
- **неизвестное**: кода нет в базе вообще.

## Быстрый старт

Требуется Python 3.8 или новее. Внешних пакетов нет, используется только стандартная библиотека (`sqlite3`, `csv`, `pathlib`).

```bash
python inventory.py
```

База `inventory.db` создается автоматически рядом со скриптом.

Рекомендуемый порядок первого запуска:

1. Пункт **1**: добавьте места с адресами.
2. Пункт **2**: внесите оборудование, сканируя коды.
3. Пункт **4**: при переездах сканируйте технику в новом месте.
4. Пункт **5**: периодически проводите инвентаризацию.

## Подключение сканера

1. Вставьте сканер в USB (или сопрягите Bluetooth-модель) и убедитесь, что он в режиме **USB HID Keyboard**.
2. Проверьте в Блокноте: код печатается, курсор переходит на новую строку. Если нет, включите суффикс Enter по инструкции сканера.
3. В программе поставьте курсор на строку «Код» и сканируйте.

Для кодов с буквами переключите раскладку на английскую.
